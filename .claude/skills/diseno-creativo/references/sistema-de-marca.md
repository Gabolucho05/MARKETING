# Sistema de Marca

Nunca se diseña sin sistema, aunque sea uno mínimo declarado en el momento. Esta fase define o carga las reglas visuales que toda pieza posterior debe respetar.

## 1. Buscar un sistema existente primero

Antes de construir uno desde cero, revisar si ya existe:
- Un manual de marca previo producido por esta misma skill (documento anterior en la conversación o guardado en el repositorio del cliente).
- El resultado de la skill `market-brand` (voz de marca) — comparte cliente/marca con esta skill; si existe un `BRAND-VOICE.md`, es la fuente de verdad para tono y mensaje, y esta skill construye la fuente de verdad visual sobre esa base, no en paralelo ni contradiciéndola.

Si existe cualquiera de los dos, se usa como está — no se re-inventa el sistema de marca en cada pieza nueva.

## 2. Componentes mínimos de un sistema de marca

Si no existe nada, construir al menos esto antes de producir una sola pieza:

| Componente | Qué define |
|---|---|
| **Paleta de color** | Color primario, 1-2 secundarios, neutros (fondo/texto). Con códigos hex reales, no "azul corporativo" |
| **Tipografía** | Una para títulos, una para cuerpo (pueden ser la misma familia en distintos pesos). Evitar defaults genéricos salvo que ya sean del cliente (ver regla no negociable #1 de `SKILL.md`) |
| **Tono visual** | ¿Minimalista, cálido/artesanal, corporativo serio, juguetil/urbano? En una frase, no un párrafo |
| **Uso del logo** | Versión principal, versión sobre fondo oscuro/claro, área de resguardo mínima, qué NO hacer con el logo (deformarlo, ponerlo sobre fondos que no contrastan) |
| **Estilo de imagen/fotografía** | ¿Fotografía real de personas venezolanas en contexto, ilustración, producto en estudio, UGC crudo? Esto conecta directo con los ángulos de venta que produce `paid-media` — el estilo visual debe encajar con el ángulo, no pelear contra él |
| **Elementos gráficos recurrentes** | Formas, texturas o patrones que identifican la marca más allá del logo (si existen) |

## 3. Cómo construirlo cuando no existe nada

Preguntar (máximo 3-5 preguntas de una sola tanda, no interrogatorio):
1. ¿Hay colores/logo ya definidos, aunque sea informalmente (ej. "siempre usamos este verde")?
2. ¿Cómo se describiría la marca en 3 adjetivos?
3. ¿Hay referencias de marcas (propias o de otra categoría) que capturan el tono deseado?
4. ¿Hay restricciones (ej. el logo no se puede modificar, ya hay tipografía comprada)?

Con esas respuestas, proponer paleta + tipografía + tono en un documento corto — no una sesión de branding completa salvo que el cliente la pida explícitamente. Marcar cualquier elemento inventado/propuesto (vs. confirmado por el cliente) para que quede claro qué está aprobado y qué es sugerencia.

## 4. Control de calidad contra el sistema (antes de cada entrega)

Antes de entregar cualquier pieza (Paso 4 del flujo principal), verificar:
- ¿Respeta la paleta y tipografía definidas, o se coló un color/fuente fuera de sistema?
- ¿El tono visual coincide con el tono de marca declarado (no un flyer "corporativo serio" para una marca que se definió como "juguetil/urbana")?
- ¿Evita los clichés genéricos de IA? (ver regla no negociable #1 de `SKILL.md`: nada de tipografías trilladas por defecto, ni grids de cards idénticos "de SaaS genérico")
- ¿Tiene un solo anclaje visual claro?

## 5. Consistencia entre piezas de una misma campaña

Todas las piezas de una campaña comparten paleta, tipografía y tratamiento visual, aunque el ángulo de venta (de `paid-media`) cambie de una pieza a otra. El ángulo cambia el mensaje y el foco emocional; el sistema de marca no cambia nunca dentro de la misma campaña.
